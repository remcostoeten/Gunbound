title: Quick Start Guide
description: The shortest path to running Gunbound locally.
---

This quickstart is for developers, not end users. It assumes you want the repo running
locally and you need the client, the SpacetimeDB module, and the docs to line up.

## Prerequisites

- Bun
- SpacetimeDB CLI
- A cloned checkout of this repo

## 1. Start The Main Dev Flow

From the repository root:

```bash
bun run dev
```

That opens the terminal process manager. It starts the Next.js app and the local SpacetimeDB
server, then lets you start the module watcher from the same screen.

The Next.js app is on `http://localhost:3000`.
The local SpacetimeDB websocket endpoint defaults to `ws://127.0.0.1:3002`.

## 2. Start The Module Watcher

In the process manager, start the `STDB Module` process, or run:

```bash
bun run spacetime:dev
```

Use the reset variant if you want a clean local database:

```bash
bun run spacetime:dev:reset
```

## 3. Publish Or Regenerate Manually

If you edit the server module directly, the usual loop is:

```bash
bun run spacetime:publish:local
bun run spacetime:generate
```

Use those when you want to push schema or reducer changes without relying on the watcher.

## 4. Work On The Docs Only

If you only want the docs app:

```bash
cd docs
bun run dev
```

## 5. Common Checks

```bash
bun run build
cd docs && bun run types:check
git status
git diff
```

## What To Expect

- Client actions call generated reducers.
- Reducers mutate authoritative tables on the server.
- Subscriptions push table changes back to the client.
- Generated bindings update after schema or reducer changes.

## Typical Edit Loop

1. Change server or client code.
2. Regenerate bindings if the SpacetimeDB schema changed.
3. Refresh the browser.
4. Check `git diff` before you stop.
