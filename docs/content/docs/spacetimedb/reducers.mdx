---
title: Reducers & Mutations
description: Server-side state changes and transactional logic
---

All mutations go through reducers in `server/spacetimedb/src/index.ts`. Client calls use camelCase: `create_room` → `createRoom`.

## Calling reducers

```typescript
const conn = useSpacetimeDB().getConnection();
if (!conn) throw new Error('not connected');

await conn.reducers.registerCredential({ username, encryptedToken });
await conn.reducers.createRoom({ code: 'AB12', seed: 42n });
await conn.reducers.setReady({ roomId: 5n, isReady: true });
```

Reducers are transactional, deterministic, and return nothing to the caller. Failures throw `SenderError` with a message string.

## Lifecycle hooks

| Hook | Behavior |
| --- | --- |
| `onClientConnected` | Upsert `player`, apply login streak XP, cleanup orphan waiting rooms |
| `onClientDisconnected` | Set `isOnline: false`, leave queue, evict from **waiting** rooms only |

Mid-match room membership is preserved across disconnect so players can reconnect.

## Auth

### registerCredential

`{ username, encryptedToken }` — binds username to `ctx.sender`, rejects duplicate username or duplicate identity.

### updateCredentialToken

`{ username, encryptedToken }` — replaces ciphertext for the caller's existing row (password change flow). Server reducer exists; wire up client UI when exposing password updates.

## Rooms

### createRoom

`{ code, seed }` — host becomes first `room_member` with empty `mobileType`. Defaults: map `rolling`, target score 2, round limit 5, timed turns.

### updateRoomSettings

`{ roomId, mapType, targetScore, roundLimit, turnDurationMode }` — host only, `waiting` status only.

### joinRoomByCode

`{ code }` — joins a `waiting` room; idempotent if already a member. Max 2 members.

### leaveRoom

`{ roomId }` — removes member; transfers host or ends room if empty.

### kickFromRoom

`{ roomId, identity }` — host only, waiting rooms only.

## Match flow

### selectMobile

`{ roomId, mobileType }` — must be a valid mobile string; blocked during active rounds.

### setReady

`{ roomId, isReady }` — note **`isReady`**, not `ready`.

### startRound

`{ roomId, seed }` — host only; all members ready with mobiles selected; creates a `round` row and sets room status to `in_match`.

### recordRoundEvent

`{ roundId, tick, kind, payload }` — append-only battle sync; validates turn order and payload shape.

### submitRoundStats

`{ roundId, damageDealt, shotsFired, directHits }` — once per player per round, before `endRound`.

### endRound

`{ roundId, winnerIdentity? }` — host only; optional winner (omit for draw); awards XP and resets ready flags.

## Update pattern

Always spread the existing row when updating:

```typescript
const room = ctx.db.room.id.find(roomId);
ctx.db.room.id.update({ ...room, status: ROOM_STATUS.IN_MATCH });
```
