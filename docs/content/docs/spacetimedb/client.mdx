## Provider setup

`GunboundSpacetimeProvider` wraps the app and builds a single SpacetimeDB connection:

```typescript
// src/features/game/spacetime/connection.tsx
export function GunboundSpacetimeProvider({
  children,
  onIdentity,
  sessionKey
}: {
  children: ReactNode;
  onIdentity?: (identity: Identity) => void;
  sessionKey?: string | number;
}) {
  const [connectionRetry, setConnectionRetry] = useState(0);

  const connectionBuilder = useMemo(() => {
    const storedToken = readStoredToken();
    return DbConnection.builder()
      .withUri(createConnectionUri(connectionRetry, sessionKey))
      .withDatabaseName(SPACETIME_MODULE)
      .withToken(storedToken)
      .onConnect((_connection, identity, token) => {
        writeStoredToken(token);
        if (onIdentity) onIdentity(identity);
      })
      .onConnectError((_connection, error) => {
        if (storedToken && isStoredTokenVerificationError(error)) {
          clearStoredToken();
          setConnectionRetry((value) => value + 1);
        }
      });
  }, [connectionRetry, onIdentity, sessionKey]);

  return (
    <SpacetimeDBProvider connectionBuilder={connectionBuilder}>
      {children}
    </SpacetimeDBProvider>
  );
}
```

**Important details:**

- Token is read from `localStorage` on mount and refreshed in `onConnect`.
- Invalid stored tokens are cleared and the connection retried automatically.
- `sessionKey` changes the websocket URL query string so the provider can remount after login without stale state.
- There is **no** `subscribeToAllTables()` in the provider — subscriptions are created by `useTable()` (see [Subscriptions](/docs/spacetimedb/subscriptions)).

## Mounting

```typescript
// src/features/home/home-screen.tsx
<SpacetimeAuthProvider>
  <GunboundSpacetimeProvider sessionKey={spacetimeSessionKey}>
    <HomeScreenInner bumpSession={() => setSpacetimeSessionKey((v) => v + 1)} />
  </GunboundSpacetimeProvider>
</SpacetimeAuthProvider>
```

After login, `bumpSession()` remounts the provider so the recovered token is picked up immediately.

## useSpacetimeDB

```typescript
const connection = useSpacetimeDB();
const conn = connection.getConnection();

if (!conn) return <div>Connecting…</div>;

await conn.reducers.createRoom({ code: 'AB12', seed: 12345n });
```

Useful fields: `connection.identity`, `connection.token`, `connection.isActive`, `connection.connectionError`.

## useTable

```typescript
import { useTable } from 'spacetimedb/react';
import { tables } from '@/features/game/spacetime';

const [players, isReady] = useTable(tables.player);
const [rooms] = useTable(tables.room);
```

Returns `[rows, isReady]`. `isReady` means the subscription has applied initial data — not a generic network spinner.

Filtered queries:

```typescript
const waitingRooms = tables.room.where((row) => row.status.eq('waiting'));
const [rooms, ready] = useTable(waitingRooms);
```

## Domain hooks

Business logic lives in `src/features/lobby/spacetime/` and `src/features/game/spacetime/`:

| Hook | Role |
| --- | --- |
| `useLobbyRooms` | Room list, create/join/quick join |
| `useRoomSession` | Members, chat, ready/mobile actions for one room |
| `useMatchmakingQueue` | Queue join/leave |
| `useLobbyFriends` / `useLobbyChat` | Social features |
| `useCurrentPlayer` / `useCurrentRoom` | Session context for home/battle routing |
| `useBattleEventSync` | Multiplayer round event sync |

Example — `useLobbyRooms` derives member count from `room_member` and calls reducers with current signatures:

```typescript
await conn.reducers.createRoom({ code, seed: generateSeed() });
await conn.reducers.joinRoomByCode({ code: code.trim().toUpperCase() });
```

## Error handling

Reducers throw `SenderError` messages to the client:

```typescript
try {
  await conn.reducers.joinRoomByCode({ code });
} catch (err) {
  showError(err instanceof Error ? err.message : String(err));
}
```
