## Product limitations

### No email-based recovery

Forgotten passwords mean a lost account. Users must store credentials in a password manager.

### Password change UI

The server exposes `updateCredentialToken` for re-encrypting the stored token after a password change. There is no full password-change flow in the auth UI yet.

### Single-factor authentication

Password only — no 2FA.

### No server-side login rate limiting

Brute-force against encrypted tokens is mitigated by PBKDF2 (150k iterations) on the client, but there is no per-IP throttle on credential reads.

### Username enumeration

The `credential` table is public; usernames are discoverable. Acceptable for a game; encryption is the access control.

## Technical constraints

### BigInt serialization

```typescript
JSON.stringify({ roomId: roomId.toString() }); // not 5n directly
```

### Identity comparison

Always use `.toHexString()` — object reference equality fails.

### Timestamps

```typescript
new Date(Number(row.createdAt.microsSinceUnixEpoch / 1000n));
```

### Optional fields

Use optional chaining — `.optional()` columns can be `null`.

### Multi-column indexes

Filter manually on non-indexed columns after an index lookup.

### One transaction per reducer

Combine related mutations into a single reducer when you need atomicity across steps.

### Encrypted token size cap

2048 characters max in `registerCredential` / `updateCredentialToken`.

## Operational notes

### Publish and generate

```bash
bun run spacetime:publish:local      # dev publish
bun run spacetime:generate           # refresh bindings
bun run spacetime:publish:local:reset  # wipe local data
```

Do not use `--delete-data` / reset flags against production.

### Module name

Must match everywhere: `gunbound` in publish commands and `SPACETIME_MODULE` in client config.

### Local URI

Default: `ws://127.0.0.1:3002` (SpacetimeDB server, not Next.js on `:3000`).

### Stale bindings

After schema edits, always run `bun run spacetime:generate` before trusting TypeScript types.

## Performance

- Avoid `[...ctx.db.table.iter()]` in reducers at scale — use index `.filter()`.
- Room capacity is 2; subscription payload stays small for typical sessions.
- Local SpacetimeDB is in-memory; use Maincloud for durable production hosting.

## Debugging

```bash
bun run spacetime:logs
```

Browser:

```typescript
localStorage.getItem('gunbound:spacetime-token');
localStorage.getItem('gunbound:username');
```

Invalid tokens are cleared automatically by `GunboundSpacetimeProvider` on connect error.
